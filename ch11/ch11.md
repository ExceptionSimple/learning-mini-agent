# ch11 变更说明（对比 ch10）

> 一句话：ch11 的核心变化是引入 **Prompt 分段组装**——把 ch10 在 `main.py` 里"一行内联拼到底"的 system prompt，抽到 `prompt.py` 拆成**静态段 + 动态段**：身份人设 / 工具清单 / 技能目录 / 记忆索引按真实状态按需拼接，并用确定性 `json.dumps` 做进程内缓存。

## 2. 核心变化：system prompt 分段组装

### 2.1 旧做法的问题（ch10）

ch10 只在**新会话**（`len(messages)==0`）里拼一次 system，是纯内联字符串：

```python
# ch10/main.py
'content': (
    f'你是一个编程助手，堪比 Claude Code！你的工作目录在 {WORKDIR} 下\n'
    f'{build_system_prompt_for_skills()}\n'
    f'{build_memory_system_prompt()}'
)
```

这段写法的三个痛点，正是 ch11 要解决的：

1. **模型看不到真实工具清单**——system 里只有 persona / skills 目录 / 记忆目录，没有任何一行告诉模型它手上能调哪些工具（工具列表只存在于 API 的 `tools=` 参数）。工具增删、改名都无人向模型"自报家门"。
2. **无条件、无分隔、顺序无承诺**——skills 片段和记忆片段不管有没有内容都 `\n` 硬拼；对服务端 prefix 缓存不友好（顺序变了就缓存失效）。
3. **写死在 main 的业务流里**——拼接逻辑与主流程耦合，想加/换一个 section 得改 `main()`。

### 2.2 prompt.py 的结构

```python
# ch11/prompt.py
PROMPT_SECTIONS = {
    "identity": f"你是一个编程助手，堪比 Claude Code！你的工作目录在 {WORKDIR} 下。",
    "subagent": "For complex sub-problems, use the task tool to spawn a subagent.",
    "todo_reminder": "<reminder>遇到编辑代码任务时，记得要更新 todo 列表</reminder>",
    "tools": "Available tools: {tool_list}.",
    "skills": "Skills available:\n{skill_catalog}\nUse load_skill to get full details when needed.",
    "memory_index": "Memories available:\n{memories}",
}
STATIC_SECTIONS = ["identity", "tools", "subagent", "todo_reminder"]
```

- **`PROMPT_SECTIONS`**：每段是一个模板，带 `{...}` 占位符的段在组装时 `.format()` 填入真实值。
- **`STATIC_SECTIONS`**：始终加载的段，且**顺序固定**——这是刻意的：稳定前缀才能命中服务端 prompt prefix 缓存（注释里写明了这一动机）。
- **`identity`**：保留 ch10 的中文人设并把工作目录并入（原英文 workspace 段并入后删除，system 开头与原实现逐字一致）。

## 3. 设计收益

1. **模型"知道"自己的工具**：tools 段把真实 schema 名喂给模型，且工具增删自动反映——这是相对 ch10 最实质的行为改进。
2. **静态段与动态段分离**：稳定前缀（identity/tools/subagent/todo_reminder）与按需内容（skills/memory_index）解耦；动态段"有才出现"，system 精简。
3. **组装与主流程解耦**：拼 system 的逻辑从 `main()` 里挪到 `prompt.py`，新增/调整 section 只需改模板表，main 只做 `update_context → get_system_prompt` 两步。
4. **进程内缓存**：用确定性 `json.dumps` 做 cache key，避免同一进程对相同 context 重复拼字符串；配合静态段顺序稳定，进一步引导服务端 prefix 缓存命中。
5. **人设零回归**：system 开头与原实现逐字一致（中文 persona + 工作目录），改名不改变既有行为。

## 4. 注意点

1. **`todo_reminder` 段提前"剧透"了 ch13**：文案提示模型"记得更新 todo 列表"，但本项目到 ch11 为止**还没有 todo / task 工具**（task 工具是委派子代理，不是建任务清单）。该段保留了教学参考文案，模型无法执行也无害；如不想要可把该段从 `STATIC_SECTIONS` 摘掉或换文案。
2. **记忆"行为引导"句被省掉了**：ch10 的 `build_memory_system_prompt()` 尾部有 `Relevant memories are injected below… When the user says 'remember' … extract it as a memory.` 一句引导。ch11 的 memory_index 段只放索引目录，这句不再进 system——但因为 `after_turn_call` 的抽取是**每轮无条件执行**、不依赖模型自我提醒，行为上不受影响；若想保留提示可把该句并回 identity 或 memory_index 模板。
3. **缓存只对"最后一次 context"有效**：`_last_context_key` 是单槽缓存；`get_system_prompt` 每会话只调一次，命中场景有限，属轻量进程内优化。真正有意义的是静态段顺序稳定、可被服务端 prefix 缓存命中——前提是不要随意调整 `STATIC_SECTIONS` 顺序或往 identity 前插动态内容。
4. **`identity` 含绝对路径**：跨目录/跨机器恢复 `.sessions` 会话时，persona 里的工作目录会指向拼接时的 cwd（与 ch10 相同，属可接受）。
5. **`build_system_prompt_for_skills` / `build_memory_system_prompt` 成为孤儿**：它们仍以公开函数存在于 `skills.py` / `memory.py`，但 main 已不调用（职责被 prompt.py 取代）。教学上建议留作对照，不必急着删。
