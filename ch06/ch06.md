# ch06 变更说明（对比 ch05）

> 一句话：ch06 的核心变化是引入 **Hook 事件系统**，把权限检查、会话持久化等**横切关注点**从 Agent 主逻辑中剥离，改为通过注册回调（hook）注入。
> ch05 打下的"分层 + 类型化对象 + 依赖注入"地基不变，ch06 在其上加了一层"可插拔的扩展点"。

## 2. 核心变化：Hook 事件系统

### 2.1 事件注册表 + 注册/触发

ch05 没有事件机制，Agent 主循环里内联处理所有横切逻辑。ch06 新增 `hook.py`：

```python
HOOKS = {
    "before_tool_call": [],   # 调用工具之前
    "after_tool_call": [],    # 调用工具之后
    "before_llm_call": [],    # 调用 LLM 之前
    "after_llm_call": [],     # 调用 LLM 之后
    "after_turn_call": []     # 一轮 Turn 之后（ch06 新增）
}

def register_hook(event: str, callback):   # 注册回调
    HOOKS[event].append(callback)

def trigger_hook(event: str, *args):       # 触发，回调返回非 None 即短路
    for callback in HOOKS[event]:
        result = callback(*args)
        if result is not None:
            return result
    return None
```

### 2.2 两个 Hook Context

事件回调通过 Context 对象共享数据，不再靠散落的参数：

- **`ToolCallHookContext`**：工具调用上下文（`tool_name` / `tool_input` / `tool` / `agent` / `tool_result` / `raw_tool_result` / `messages`）
- **`LLMCallHookContext`**：LLM / Turn 级上下文（`agent` / `llm` / `messages` / `session_id` / `response`）

### 2.3 事件一览

| 事件 | 挂载方 | 作用 |
|---|---|---|
| `before_tool_call` | `core/agent.py` | 权限检查（取代 ch05 内联 `check_permission`） |
| `after_turn_call` | `main.py` | 会话持久化 `write_sessions`（取代 ch05 内联调用） |
| `before_llm_call` / `after_llm_call` | 预留 | LLM 请求前后扩展位（ch06 定义了 Context，尚未注册回调） |

## 3. 横切关注点：从"内联"变为"Hook"

### 3.1 权限检查

ch05 在 Agent 循环内联：

```python
# ch05 —— 内联
if not check_permission(tool):
    messages.append({"role": "tool", "tool_call_id": tool.tool_id, "content": "Permission denied."})
    continue
```

ch06 注册为 `before_tool_call` 回调，Agent 循环只做 `trigger_hook`：

```python
# ch06/core/agent.py —— 注册
def before_tool_call(context: ToolCallHookContext) -> bool:
    if not check_permission(context.tool):
        context.messages.append({"role": "tool", "tool_call_id": context.tool.tool_id, "content": "Permission denied."})
        return False
    return True
register_hook("before_tool_call", before_tool_call)

# ch06/core/agent.py —— 循环内只触发
tool_call_context = ToolCallHookContext(
    tool_name=tool.name, tool_input=tool.tool_input, tool_result='',
    messages=messages, tool=tool,
)
if not trigger_hook("before_tool_call", tool_call_context):
    continue
```

### 3.2 会话持久化

ch05 在 `main()` 内联：

```python
# ch05 —— 内联
agent.agent_loop(messages=messages)
write_sessions(session_id=session_id, messages=messages)
```

ch06 注册为 `after_turn_call` 回调：

```python
# ch06/main.py —— 注册
def after_turn_call(context: LLMCallHookContext):
    cprint("[HOOK] after_turn_call", color="grey")
    return write_sessions(session_id=context.session_id, messages=context.messages)
register_hook("after_turn_call", after_turn_call)
```

**收益**：Agent / main 主逻辑不再关心"权限怎么判、会话怎么存"，这些关注点可以独立增删、替换、叠加，不影响编排核心。

## 4. 其它变化

1. **`utils/color_print.py` 新增**：集中 ANSI 颜色码，`cprint` / `colorize` 支持前景色、背景色、样式与 `grey` 别名。hook 日志（`[HOOK] ...`）统一用它打灰色，替代散落的 `\033[xxm`。
2. **LLM 级 Hook 预留**：`LLMCallHookContext` 与 `before_llm_call` / `after_llm_call` 事件先定义好，为后续在 LLM 请求前后挂载逻辑（如日志、重试、缓存）留位。
3. **循环导入解法**：`hook.py` 仅在类型注解中使用 `Agent`，改用 `from __future__ import annotations` + `if TYPE_CHECKING:` 延迟导入，切断 `core.agent ↔ hook` 的循环。

---

## 5. 设计收益

1. **横切关注点解耦**：权限、持久化、日志从 Agent 主循环剥离，Agent 只负责"编排 LLM + 执行工具"。
2. **可插拔扩展**：不改核心代码即可新增行为（多一个 `register_hook` 即可），符合开闭原则。
3. **Context 传递数据**：回调间数据共享有结构（不再用裸参数飞来飞去）。
4. **短路语义**：`trigger_hook` 返回第一个非 None 结果，可用作"拦截/放行"（如 `before_tool_call` 返回 False 拒绝）。

---

## 6. 注意点

1. **Hook 回调返回值约定**：目前 `before_tool_call` 用"返回 False 拦截"，`after_turn_call` 用"返回值非 None 短路"，两种语义并存，后续若回调增多需统一约定。
2. **`ToolCallHookContext` 构造**：传参必须写 `tool_name=tool.name`（`ToolCall` 对象的字段是 `name`，不是 `tool_name`），并补传 `tool=tool`，否则 `before_tool_call` 里 `check_permission(context.tool)` 会拿到 `None`。
3. **Context 字段名单复数**：`messages` 字段务必用复数 `self.messages`，`agent.py` 通过 `context.messages` 追加消息，若存成 `self.message` 会在权限拒绝路径抛 `AttributeError`。
