## 2. 核心变化：Skills 机制

### 2.1 什么是 skill

一个 Skill = `skills/` 下的**一个目录** + 目录内**一份 `SKILL.md`**。`SKILL.md` 头部是 YAML frontmatter（`name` + `description`），正文是给模型看的详细操作说明。

ch08 的接入采用"**目录先行 + 正文懒加载**"两段式，这也是 Claude Code 真实 skills 机制的雏形：

1. **启动时注入清单**：`main.py` 启动即 `scan_skills()` 扫描 `skills/` 目录，`build_system_prompt_for_skills()` 把技能名清单拼进 system prompt。模型一开始只看到一串技能名，上下文占用极小。
2. **按需加载全文**：模型需要某个技能时，调用 `load_skill` 工具，把该技能 `SKILL.md` 的**完整正文**拉进上下文。

## 4. 设计收益

1. **能力复用**：把"怎么做某件事"沉淀成 `SKILL.md`，任何一次会话都能通过 `load_skill` 取用，不必每次重新描述。
2. **上下文克制**：目录只占一行 `<skill>name</skill>`，正文只在真正需要时才加载——避免把一堆技能手册一次性塞满上下文。
3. **零新机制**：`load_skill` 完全复用既有的 `StructuredTool` / `tool_to_openai`，与 `bash`、`task` 等工具同构，注册即用。
4. **声明式扩展**：新增技能 = 新增一个目录 + 一份 `SKILL.md`，不改任何代码（`_scan_skills` 自动发现）。
5. **与 Subagent 互补**：`task` 委派"执行"（开新上下文去干活），`load_skill` 供给"知识"（把手册拉进当前上下文），两者解决不同问题。

---

## 5. 注意点

1. **注册表 key 是 frontmatter 的 `name`，不是目录名**：示例技能的 key 是中文名 `宠物小精灵 · 天命匹配师`，因此 `load_skill("pokemon")` 会返回 `Skill 'pokemon' not found.`，必须传 `load_skill("宠物小精灵 · 天命匹配师")` 才命中。若希望"目录名 == 技能名"，需统一 frontmatter 的 `name` 与目录名。
2. **`load_skill` 返回原文含 frontmatter**：返回的是 `SKILL.md` 原始全文（`---` 头也在内），模型需自行忽略头部。若介意可改为只返回 `body`。
3. **`_scan_skills` / `scan_skills` 命名易混**：`_scan_skills()` 才是真正扫描注册的逻辑，`scan_skills()` 是"扫描 + 打印"的公开入口；两处 `[SKILLS]` 打印混在 `scan_skills()` 里，与扫描职责耦合。
4. **`build_system_prompt_for_skills` 仅在新会话注入**：system prompt 只在 `len(messages) == 0`（新会话）时拼接；已恢复的历史会话不含技能目录，若中途新增技能，老会话看不到。
5. **`reasoning_content` 仍只记录不消费**：ch08 的 `agent_loop` 沿用了 ch07 补充的 `reasoning_content` 累加（暂无下游使用），`answer_content` 才是生效部分。
